# Credential Management Guide

**Version**: 1.0  
**Date**: 2026-08-17  
**Feature**: 006-k3d-disaster-recovery

## Overview

This document describes credential management for the k3d disaster recovery system.

## Credentials Overview

### 1. Kopia Repository Password

**Purpose**: Encrypts backup data in the Kopia repository.

**Storage**: Environment variable `KOPIA_PASSWORD`

**Usage**:
```bash
export KOPIA_PASSWORD="your-secure-password"
```

**Security**:
- Never commit to version control
- Use a strong, unique password
- Store in a secure vault or password manager
- Rotate periodically

### 2. Vault Unseal Key

**Purpose**: Auto-unseals Vault during restore.

**Storage**: File on host filesystem (default: `/path/to/vault-unseal-key`)

**Usage**:
```bash
# Create unseal key file
vault operator generate-key > /path/to/vault-unseal-key

# Set permissions
chmod 600 /path/to/vault-unseal-key
```

**Security**:
- Store in a secure location
- Use restrictive permissions (0600)
- Backup to secure storage
- Never commit to version control
- Rotate periodically

### 3. Kubernetes Secrets

**Purpose**: Store application secrets in the cluster.

**Storage**: Kubernetes Secrets (generated by Vault/ESO)

**Usage**:
```bash
# Secrets are managed by Vault and ESO
# Do not create manually
```

**Security**:
- Never store in version control
- Use external secret management
- Rotate regularly
- Audit access

## Best Practices

### 1. Use External Secret Management

- Use Vault for all secrets
- Use ESO to sync secrets to Kubernetes
- Never store secrets in code or configuration files

### 2. Implement Least Privilege

- Grant minimal permissions required
- Use role-based access control
- Audit access regularly

### 3. Rotate Credentials

- Rotate Kopia password periodically
- Rotate Vault unseal keys periodically
- Rotate application secrets regularly

### 4. Secure Storage

- Store credentials in secure vaults
- Use encrypted storage for backups
- Implement access controls

### 5. Audit and Monitor

- Log credential access
- Monitor for unauthorized access
- Review access regularly

## Configuration

### backup-config.yml

```yaml
kopia:
  repository_path: /path/to/kopia-repository
  password_env: KOPIA_PASSWORD  # Environment variable name
  
vault:
  namespace: vault
  unseal_key_path: /path/to/vault-unseal-key
```

### Environment Variables

```bash
# Required
export KOPIA_PASSWORD="your-secure-password"

# Optional
export VAULT_ADDR="https://vault.example.com"
export VAULT_TOKEN="your-vault-token"
```

## Backup Procedures

### Backup Kopia Password

1. Export password to secure file:
   ```bash
   echo "$KOPIA_PASSWORD" > /secure/backup/kopia-password.txt
   chmod 600 /secure/backup/kopia-password.txt
   ```

2. Store in password manager

3. Document recovery procedure

### Backup Vault Unseal Key

1. Copy unseal key to secure location:
   ```bash
   cp /path/to/vault-unseal-key /secure/backup/
   chmod 600 /secure/backup/vault-unseal-key
   ```

2. Store backup in multiple secure locations

3. Document recovery procedure

### Backup Kubernetes Secrets

1. Export secrets:
   ```bash
   kubectl get secret <secret-name> -n <namespace> -o yaml > secret-backup.yaml
   ```

2. Store in secure location

3. Document recovery procedure

## Recovery Procedures

### Recover Kopia Password

1. Retrieve from secure storage
2. Set environment variable:
   ```bash
   export KOPIA_PASSWORD="recovered-password"
   ```

### Recover Vault Unseal Key

1. Retrieve from secure storage
2. Copy to original location:
   ```bash
   cp /secure/backup/vault-unseal-key /path/to/vault-unseal-key
   chmod 600 /path/to/vault-unseal-key
   ```

### Recover Kubernetes Secrets

1. Retrieve backup from secure storage
2. Apply to cluster:
   ```bash
   kubectl apply -f secret-backup.yaml
   ```
